# Вайрфрейми

Структура екранів і потоки без кольору й типографіки — тільки ієрархія та логіка.

Два робочі документи, від яких залежить усе інше в цій папці:

- [`_screens.md`](_screens.md) — **що малюємо**: екрани головного flow, job під кожним,
  місце у потоці й перелік реальних станів. Замовлення, а не опис.
- [`_conventions.md`](_conventions.md) — **як малюємо**: деталізація, семантична розмітка,
  текст із домену, іменування файлів, правило станів.

## Ключові потоки

1. **Онбординг** — що бачить людина до першого питання, щоб довіритись на 20 питань
2. **Опитувальник** — 5 блоків, прогрес, автозбереження, розгалуження
3. **Червоні прапорці** — пріоритетний алерт **над** планом; опитувальник не переривається
4. **План** — базовий шар + ризик-орієнтований, джерела, дисклеймер
5. **Порожній-але-не-порожній план** — для 18–25: чому зараз більше нічого не потрібно
6. **Відмітка пройденого** — дата → перерахунок наступної
7. **Експорт** — PDF і резервна копія разом із вкладеннями

Потоки 1–5 входять у [поточне замовлення](_screens.md); 6 і 7 — крок 8, разом
з рештою flow.

**Іменування:** `<назва>.html` для базового екрана, `<назва>-<стан>.html` для кожного
стану, латиницею — [повний перелік файлів](_conventions.md#4--файли-й-іменування).
